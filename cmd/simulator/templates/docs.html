Matter devices (matter.js)

The simulator can emulate commissionable Matter devices via matter.js: temperature & light sensors, smart plug (with energy), EVSE charger, thermostat, heat pump, dishwasher and washing machine. Create one with POST /api/simulators using a matter_* type.

Requires Node.js on the host (v18+, v20+ recommended). The app spawns a managed Node bridge; if Node is missing, Matter is disabled — check GET /api/matter/status.
Each device exposes a manual pairing code and a MT: QR payload for commissioning into Home Assistant / Apple Home / Google Home.
Test Vendor ID / DCL test-net: simulated devices use the CSA test Vendor ID 0xFFF1 and a test Product ID. These are not registered in the production Distributed Compliance Ledger (DCL).
To pair into Home Assistant, enable the Matter Server's test / Test-Net DCL option (allow non-certified / test devices). Apple Home and Google Home will warn about an "uncertified accessory"; use a developer/test controller for reliable testing.

Typical flow: create the device (POST /api/simulators) → start its simulation loop (POST /api/simulators/{id}/automation/start) → read pairing_code / qr from GET /api/simulators/{id} → commission it into your controller → control it via POST /api/simulators/{id}/state with {"key", "value"}.

Each device has built-in physics that emulate real usage while automation runs (diurnal sensor curves, thermostat thermal model, plug/EVSE/heat-pump power draw with accumulating energy, timed appliance cycles). Control keys per type — e.g. on/load_w (plug), plugged/charging/max_current_a (EVSE), heating_setpoint_c/system_mode (thermostat/heat pump), start/stop (appliances), temperature_c/lux/auto (sensors) — are documented in docs/MATTER.md. Changes made from a paired Home app flow back into the simulation.

Matter commissioning needs LAN multicast (mDNS). It works in desktop mode and Docker host networking; under Docker bridge networking devices won't be discoverable.

MCP (Model Context Protocol)

Agents can control the simulator through the MCP endpoint. This MCP server exposes one tool per HTTP API endpoint plus a generic api_request tool for any path.

Endpoint: /mcp (JSON-RPC 2.0, streamable HTTP)
Discovery: /.well-known/mcp
Base URL: http://localhost:8762

The base URL is the origin of the app window. In desktop mode it is typically http://localhost:8762. In Docker/server mode it is usually http://localhost (or your host IP).

Initialize

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {}
}

List Tools

{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/list",
  "params": {}
}

Call a Tool

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "simulators.list",
    "arguments": {}
  }
}

Streamable HTTP (SSE)

Set Accept: text/event-stream or append ?stream=true to get SSE responses.

curl -N -H "Accept: text/event-stream" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":4,"method":"tools/list"}' \
  http://localhost:8762/mcp

Generic API Tool

{
  "jsonrpc": "2.0",
  "id": 5,
  "method": "tools/call",
  "params": {
    "name": "api_request",
    "arguments": {
      "method": "POST",
      "path": "/api/simulators",
      "body": { "type": "inverter" }
    }
  }
}
